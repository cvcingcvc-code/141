## 2. 影响判断

1. 泄露的信息量：**零新增**。任何能看到本仓库的人，本来就能从 commit author 行读到同一邮箱。
2. 真正的问题不是"泄露了什么"，而是**它违反了 `V-010` 的机械规则**，导致隐私扫描无法给出"0 命中"的干净结论——门禁一旦经常出现例外，就会被习惯性放行。
3. 历史无法撤回：`106144d` 已公开，删除 HEAD 中的明文不改变历史。

## 4. 预防

1. 文档写 git 身份、联系方式时，一律用 `账号名` + `（邮箱见本地 git 配置）`，不写明文。
2. `V-010` 对所有文件生效（含 draft / `published:false`），校验器已实现。
3. QA 的隐私扫描白名单只允许"值级精确匹配"，禁止"文件级/目录级跳过"——否则本类事件会被静默吞掉。
