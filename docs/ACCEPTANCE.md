# ACCEPTANCE.md — 验收标准与证据要求

> 原则：**"编译成功"和"测试通过"都不是验收。** 验收的唯一形式是：人在真实环境里操作，得到可复查的证据。

## 1. 验收角色与签字

| 项 | 谁做 | 产出 |
| --- | --- | --- |
| 功能验收 | QA Agent（A5）独立执行 | `docs/qa/ACCEPTANCE-RUN-<日期>.md` |
| 集成验收 | 主 Agent（A1） | PR 中集成结论 |
| 最终验收 | 用户 | 在 PR/Issue 上明确确认 |

任何一方缺签，里程碑不算通过。A1 不得替代 A5 出验收结论，A5 不得修改业务代码让自己通过。

## 2. 证据规则

每个验收项必须留下**至少一种**可复查证据：

1. 命令 + 完整输出（粘贴到验收文档，不截断关键行）。
2. 部署/CI 运行链接（`github.com/cvcingcvc-code/141/actions/runs/<id>`）。
3. 截图路径（存 `qa/evidence/<里程碑>/<编号>.png`，且截图里能看到 URL 或时间）。
4. 终端录制或浏览器操作序列描述（步骤可被第三人复现）。

禁止的"证据"：只写"已验证"、只贴 `✓ built in 3.2s`、只给单元测试绿灯、口头确认。

## 4. 红灯用例（必须失败，失败才算通过）

| ID | 构造 | 期望 |
| --- | --- | --- |
| R-01 | knowledge `status: verified` + `sources: []` | 报 `V-009`，exit 1 |
| R-02 | `related: [KB-NOT-EXIST]` | 报 `V-008` |
| R-03 | 文件名 `kb-eng-777-x.md` 但 id 为 `KB-ENG-001` | 报 `V-006` |
| R-04 | journal `source: agent-drafted` 缺 `approved_at` | 报 `V-011` |
| R-05 | 正文含 `someone@example.com` | 报 `V-010` |
| R-06 | `tags` 给 13 项 | 报 `V-014` |
| R-07 | journal `review_status: draft` | 构建产物中不存在该条目（不报错，但不发布） |
| R-08 | 条目 `visibility: private` | 站点/搜索/`content.json` 三处均不存在 |

R-07/R-08 是"静默泄漏"类，最容易假通过，必须用产物检索验证（`grep` 产物），不能只看页面肉眼。

## 5. 用户故事验收脚本（真实操作）

每条都要写：操作步骤 → 期望 → 实际 → 证据编号。

| ID | 操作 | 期望 |
| --- | --- | --- |
| US-1 | 手机浏览器打开首页 | 首屏 3 秒内可读到"我是谁/在做什么"；有最近复盘与知识入口 |
| US-2 | 打开任一知识详情 | 能看到来源（书名/URL/页码）、`verified/seed` 徽章、更新时间 |
| US-3 | 在搜索页输入一个只出现在正文里的词 | 命中该条，点击进入正确页面 |
| US-4 | 点任一标签 | 列出该标签全部条目，数量与 `content.json` 统计一致 |
| US-5 | 打开项目详情 | 下方聚合出关联知识/错误/复盘，链接可点且不 404 |
| US-6 | 按 `docs/IMPORT.md` 走一遍录入 | 生成 draft → 校验通过但不上站 → 手动 approved 后上站 |
| US-7 | 让 Agent 尝试改非自己区域的文件 | 被 AGENTS.md 规则拒绝，或走 RFC 流程 |
| US-8 | 360px 视口通读长文 | 无横向滚动，正文可读，代码块可横向滚动而非撑破布局 |

## 6. 缺陷单格式

`docs/qa/defects/DF-<NNN>.md`

```markdown
# DF-001 <一句话现象>

- 严重级：P0 / P1 / P2
- 关联契约：C-10 / V-009
- 发现环境：URL + commit + 浏览器/视口
- 关联任务：T3.2

## 复现步骤
1. …
2. …

## 期望 / 实际
期望：…
实际：…（贴原文输出或截图路径）

## 根因
（必须定位到文件与行为；写"原因不明"视为未完成）

## 修复
- Commit：<sha>
- 变更文件：…
- 修复范围说明：为何这是最小修复

## 回归证据
- 命令/操作：…
- 结果：…
```

## 7. 验收不通过的典型情形（一律打回）

1. 用 `npm run build` 成功代替页面可用。
2. 页面能打开但数据是硬编码的假数据。
3. 搜索页能出结果但点进去 404。
4. 样本内容被当成真实内容（未标 `sample`）。
5. 修复缺陷时顺手重构无关模块（扩大范围）。
6. 验收文档里出现"应该""大概""理论上"。

## 8. 回滚标准

出现以下任一情况，立即回滚该 PR 并在缺陷单记录：
- 公开站点出现 private/draft 内容；
- `main` 构建失败；
- 内容被覆盖或删除（非本人 PR 造成）。
