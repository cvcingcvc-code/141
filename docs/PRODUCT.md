# PRODUCT.md — 产品定义与 MVP 范围

> 状态：v1.0（待批准冻结）
> 上游依据：`docs/AUDIT.md`（仓库为空，从零定义）
> 变更方式：只能经 RFC 修改，见 `docs/rfc/README.md`

## 1. 一句话定义

把一个人的介绍、知识、项目、每日复盘、踩过的坑，沉淀成**可在 git 中追溯、可被全文搜索、可逐步自动生成**的静态知识站，并让多个 Agent 能长期并行维护而不互相破坏。

## 2. 要解决的真实问题

| 问题 | 现状 | 本系统如何解决 |
| --- | --- | --- |
| 学到的东西散落在笔记软件/聊天/脑子里，三个月后失效 | 无法检索、无法验证是否真学过 | 知识条目带 `sources`，无来源必须显式标 `seed`，不允许伪装成已掌握 |
| 复盘写了但从不回看，也不和项目/错误关联 | 孤立文本，无复用价值 | 复盘条目强制链接 `knowledge` / `projects` id，形成图谱 |
| 同一个错误反复犯 | 只在当下抱怨，没有根因与预防 | 错误经验条目强制 `root_cause` / `prevention` / `evidence` 三字段 |
| 知识库越写越乱，无法长期维护 | 分类随意、格式漂移 | 受控 frontmatter + 校验器，CI 拦截不合规条目 |
| 多 Agent 协作会互相覆盖 | 无契约 | 契约冻结 + 目录写权限 + 独立分支/worktree |

## 3. 用户与场景

单一真实用户（站主本人）为内容生产者与审核者；读者是站主本人 + 可能的公开访客。

核心场景（用户故事，编号用于验收追溯）：

| ID | 场景 | 验收要求 |
| --- | --- | --- |
| US-1 | 作为访客，进入首页能立刻看懂"这个人是谁、在做什么、最近在学什么" | 首页首屏含简介 + 最近 3 条复盘 + 最近 3 条知识 + 项目入口 |
| US-2 | 作为站主，想确认某条知识是否可靠，能一眼看到来源与可信度 | 详情页固定展示来源列表、`status`、`confidence` 徽章 |
| US-3 | 作为站主，想查"我什么时候踩过这个坑"，能全文搜索命中 | 搜索页输入关键词可命中标题/摘要/正文，并高亮来源页 |
| US-4 | 作为访客，想按主题浏览知识 | 标签页与领域页可用，且能反查该标签下所有条目 |
| US-5 | 作为站主，想回顾某个项目做对了什么、错了什么 | 项目详情页聚合其关联知识、错误、复盘 |
| US-6 | 作为站主，想把今天的复盘录入系统 | 有模板 + 校验 + PR 审核流程；未审核内容不上站 |
| US-7 | 作为 Agent，想安全地改一个模块 | 目录写权限清晰，越界即被拒绝 |
| US-8 | 作为访客，在手机上阅读 | 360px 宽度无横向滚动，正文可读性达标 |

## 4. MVP（v0.1）范围

MVP 的判定标准：**五类内容各至少一条真实条目，站点可搜索，CI 能拦住坏数据，公开 URL 可访问，且全流程由一个不熟悉仓库的人按文档复现。**

### 4.1 必须做（In Scope）

| 模块 | 内容 |
| --- | --- |
| 内容模型 | profile / knowledge / projects / journal / errors 五类，受控 frontmatter（见 CONTRACTS） |
| 内容校验 | `npm run validate`：schema、id 唯一、关联不悬空、敏感信息、state 合法性 |
| 站点 | 首页、关于、知识列表/详情/标签、项目列表/详情、复盘时间线/详情、错误列表/详情、搜索页、404 |
| 搜索 | Pagefind 静态全文搜索，构建期生成，无需后端 |
| 数据导出 | `dist/data/content.json`、`dist/data/graph.json`（供站内图谱与 QA 统计） |
| 部署 | GitHub Actions → GitHub Pages，`main` 合入即发布 |
| 复盘流程 | 模板 + 校验 + PR 审核（人工批准后才发布），数据源未接通处显式标注 |
| 文档 | AGENTS / PRODUCT / ARCHITECTURE / CONTRACTS / TASKS / ACCEPTANCE / TAXONOMY / BRANCHES |

### 4.2 明确不做（Out of Scope，v0.1 一律拒绝，除非 RFC 批准）

- 任何后端服务、数据库、用户登录、评论、点赞
- 在线编辑器 / CMS 后台
- AI 自动写作或自动抓取生成个人经历（禁止编造）
- 与第三方笔记软件（Notion/飞书/微信）的实时同步 —— v0.1 仅支持"人工导入文件"，未接通的源必须在页面标注"未接通"
- 多语言、主题切换、PWA、RSS（v0.2 候选）
- 知识图谱可视化（v0.1 只导出 graph.json，不渲染力导向图）
- 性能优化专项、SEO 深度优化（只做基础 meta）

### 4.3 质量底线（不可协商）

1. 任何编造的个人经历、成绩、时间线 → 视为缺陷，不是"示例数据"。
2. 任何 `draft` / `private` 内容出现在公开站点 → P0 缺陷。
3. 任何未通过校验的内容合入 `main` → 流程事故，需回滚并记录。
4. 契约变更未经 RFC → PR 直接拒绝。

## 5. 里程碑

| 里程碑 | 交付物 | 门禁 |
| --- | --- | --- |
| M0 规划冻结 | 本轮 8 份文档 + 分支方案 | 用户批准 D1–D5 |
| M1 内容契约落地 | `schema.ts`、`content.config.ts`、五类样本条目、`validate` 脚本 | 校验器对 4 个红灯用例全部报错 |
| M2 站点骨架 | 全部页面路由 + 响应式布局 + 数据接入 | 本地 `build` 通过，360px/1280px 可读 |
| M3 搜索与数据 | Pagefind + content.json/graph.json | 真实关键词命中且跳转正确 |
| M4 自动化 | CI + 部署 + 复盘导入模板 | 公开 URL 可访问，PR 红灯生效 |
| M5 验收 | QA 报告 + 缺陷闭环 | 按 ACCEPTANCE 全部通过，用户真实操作确认 |

依赖关系：M1 是 M2/M3 的硬前置（M2 需要类型与真实数据形状）；M4 可与 M2 并行但部署门禁依赖 M1 的 `validate` 命令存在。

## 6. 成功度量（v0.1 结束时逐条核对）

| 指标 | 目标 |
| --- | --- |
| 五类内容真实条目 | 每类 ≥1，且 `status != seed` 的知识条目 ≥3 |
| 校验器拦截率 | 4 个预设红灯用例 100% 被拦截 |
| 搜索可用性 | 5 个真实关键词各命中 ≥1 条且跳转正确 |
| 移动端 | 360px 无横向滚动 |
| 可复现性 | 新人按 README 从 clone 到本地跑起来 ≤5 条命令 |
| 隐私 | 站点产物中不含任何邮箱/手机号/密钥（脚本扫描） |

## 7. 术语

- **条目（item）**：一个 Markdown 文件 + frontmatter，是内容最小单元。
- **契约（contract）**：内容字段、路由、数据产物、命令语义、分支规范的统一定义。冻结后变更需 RFC。
- **红灯用例**：故意构造的非法输入，用于证明校验器真的会失败（而非"看起来在跑"）。
- **真实验收**：由人在真实浏览器/手机上操作并留存证据，区别于单元测试通过。
