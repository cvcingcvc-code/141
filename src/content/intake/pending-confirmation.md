## 2. 我需要你提供的最小素材（每类只要一点点就够起步）

每条素材请给三样：**① 事实本身（你自己的话）② 依据（来源/时间/环境）③ 允许公开到什么程度**。

### D1-A profile（1 条，最优先）

- 你希望公开的自我描述：一句话身份 + 当前在做什么 + 这个库想解决什么。
- 允许公开的边界：能不能写行业/岗位？能不能写公司名？（不能就写"某公司"或直接省略）
- 头像/外链要不要放？（v0.1 非必需）

### D1-B knowledge（≥1 条即可解除 `W-002` 的单类缺口）

- 一条你**真正用过**的知识（技术判断、方法、取舍都行）。
- 依据：书名+章节 / URL+段落 / 你自己复现过的操作。
- 是否允许写具体项目名作为例证。

### D1-C projects（≥1 条）

- 项目是什么、你的真实角色、起止月份、技术栈。
- 至少 1 条**可验证**结果（能指向 commit / PR / 部署 / 数据）。
- 仓库或演示链接是否可以公开。

### D1-D journal（≥1 条；默认 `draft`，不发布）

- 某一天真实做了什么、学到什么（你的原话，我不代写）。
- 是否包含不适合公开的细节？若有：正文只写脱敏结论，原始记录放 `F:\141-vault\` 并用 `raw_source` 指针。

### D1-E errors（≥1 条）

- 一个真实的踩坑：现象（报错原文关键行）、发生条件、根因、修复、以后怎么防。
- 是否涉及内部系统名/同事信息（涉及则脱敏或改用 `vault_ref`）。
