# 来源核对规则（C-5 / V-009）

目的：让 `status: verified` 与 `confidence: high` 变成**可核对的断言**，而不是自我感觉。
校验器只能证明"结构合规"，证明不了"来源真的支持这条结论"——后者只能靠这张表逐项过。

## 1. `kind` 怎么选（C-4 枚举，单选）

| kind | 什么时候用 | `ref` 写什么 | `locator` 写什么 |
| --- | --- | --- | --- |
| `book` | 纸质/电子书 | 书名 + 版次（`"Pro Git, 2nd Edition"`） | 章节/页码（`Ch.3.6`、`p.112`） |
| `paper` | 论文/技术报告 | 标题 + 作者/年份 | 章节或图号（`§4.2`、`Fig.3`） |
| `url` | 网页、文档站、博客 | 可点开的完整 URL | 关键段落的小标题或时间戳 |
| `course` | 课程/讲座 | 课程名 + 平台 | 第几讲（`Lesson 4`） |
| `person` | 具体某人当面说的 | 只写角色/关系（`同事 A（同事）`），**不写姓名与联系方式** | 场合与日期（`2026-10 评审会`） |
| `experience` | 自己实际操作得出的 | 一句话描述那次操作（`CI 三次红后定位到行尾`） | 时间点或 commit |
| `agent` | AI 生成/推测 | 模型与用途（`assistant 摘要`） | — |

**`agent` 来源不算证据**：`confidence: high` 要求至少 1 个非 `agent` 来源（`V-009`），
这条规则挡的是"用自己的推测给自己背书"。

## 2. `locator` 的粒度要求

- 书/论文：必须能定位到**章**以下（章号或页码）；只写书名 = 没写位置。
- URL：能直接打开；若站点会变，把关键句摘进 `note`（**摘一句，不搬运全文**，遵守原许可）。
- `person` / `experience`：写到"何时、什么场合"，不写身份识别信息。
- `accessed` 只在确有"访问即可能变化"的来源（`url`）上必填；书籍不必填。

## 3. `status` 判定

| 取值 | 判定条件 | 采集时的问法 |
| --- | --- | --- |
| `seed` | 只是想法/听闻，未验证；`sources` 可为空 | "这条你验证过吗？还是先记下来？" |
| `verified` | 至少 1 个来源能支持结论，且我核对过来源确实这么说 | "依据在哪？我能去看吗？" |
| `stale` | 曾经成立，但技术/环境已变（超过 180 天且未复核 → `W-003`） | "这条还成立吗？" |
| `archived` | 明确不再维护，仅作历史 | — |

`sources: []` + `status: verified` = `V-009`，这是硬错误：不能既标"已核实"又说不出依据。

## 4. `confidence` 判定

| 取值 | 含义 | 必要条件 |
| --- | --- | --- |
| `low` | 单一来源 / 二手转述 / 我的推断 | — |
| `medium` | 多来源一致，或一手来源 + 我自己复现过 | — |
| `high` | 一手来源明确支持，且我在真实环境验证过 | **≥1 个非 `agent` 来源**（`V-009`） |

## 5. 五问核对（每条 `verified` 都要过）

1. **谁说的**：作者/组织是否具备该领域可信度？
2. **在哪**：`locator` 能否让第三人在 1 分钟内找到同一段话？
3. **何时**：来源的时效是否覆盖结论（快变领域：前端、工具链、API）？
4. **我复述准了吗**：正文是否有来源没说的推论？推论要么删掉，要么另起一句标"我的推断"。
5. **会不会误导**：结论的适用边界是否写清（在什么条件下不成立）？

五问里有任何一项答不上来 → `status: seed` + `confidence: low`，不要为了好看的徽章升级。

## 6. 常见错法（都会被退回）

| 错法 | 为什么不行 | 正确写法 |
| --- | --- | --- |
| `ref: "网上看的"` | 无法追溯 | 具体 URL + 段落 |
| `locator: "第 3 章"` 但书里没有第 3 章 | 编造位置 | 核对目录后再写 |
| 用 `agent` 来源撑 `confidence: high` | 自我背书（`V-009`） | 补一手来源，或降为 `medium` |
| 来源是竞品博客且原文无出处 | 二手且不可追 | 找一手，或标 `low` 并写明"二手" |
| 把他人文章整段贴进正文 | 违反原许可（ARCHITECTURE §6） | 摘一句 + 出处 + 自己的话 |
| 引用含真实姓名的聊天记录 | 第三方隐私，`V-010` 全文件拦截 | 脱敏为角色 + 走 `vault_ref` |

## 7. 与本仓库规则的对应

| 本节规则 | 契约/编号 |
| --- | --- |
| `sources` 为空不得 `verified` | C-5 / `V-009` |
| `high` 需非 `agent` 来源 | C-5 / `V-009` |
| 来源字段结构（`kind`/`ref`/`locator`/`accessed`/`note`） | C-5 / `V-003` |
| 不搬运他人全文、可追溯 | ARCHITECTURE §6（许可证） |
| 不写第三方隐私与联系方式 | C-18 / `V-010` |
| 私密原文只留指针 | C-18 / `V-020` |
